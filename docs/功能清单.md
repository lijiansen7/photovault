# PhotoVault 功能清单

> 基线版本：**App 2.0.1 / 服务端 2.0.5**（2026-11-24）
> 本文按「手机端 / 服务端 / 部署」三块列全部已实现能力，末尾写清已知限制。
> 历史变参见 [README 更新日志](../README.md#更新日志)。

---

## 0. 一句话定位

安卓手机把本地相册自动备份到自家 NAS，需要时按**原文件字节**还原回手机，
拍摄时间、GPS、相机型号、EXIF 全部保留。不压缩、不转码、不上云。

## 2. 手机端（Android · Kotlin + Compose）

### 2.1 备份

| 功能 | 说明 |
|---|---|
| 自动备份开关 | **默认关闭**。打开后才注册 WorkManager 周期任务 |
| 备份周期 | 15 分钟 / 1 小时 / 6 小时 / 1 天，四档 |
| 网络与电量约束 | 「仅在 WiFi 下上传」「仅在充电时上传」可各自独立打开 |
| 选择备份范围 | 列出手机所有相册（Camera / DCIM / Pictures / 微信…）及张数，只备份勾选的；默认全选 |
| 包含视频 | 开关控制视频是否一起备份（关闭后只传照片） |
| 立即同步 | 手动跑一次，不受自动备份开关影响 |
| 内容去重 | 按文件 SHA256 判断，已备份过的不会重复上传 |
| 失败重试 | 首页展示失败明细，支持单张重试 / 全部重试 |
| 进度可见 | 前台进度 + 系统通知，可取消 |
| 重置同步位置 | 让 App 重新扫描整个本机相册并逐张比对：已备份的不会重复上传，只是扫描变慢 |
| 手机删除同步 | 可选：「手机删除后，NAS 也移入回收站」。只处理本机备份过且本地已消失的照片，只做软删除；本机相册读不到或缺失超过 80% 时整轮跳过，避免误判成「删光了」 |

### 2.2 浏览与整理（相册页）

| 功能 | 说明 |
|---|---|
| 分页加载 | 每页 300 项，滚到接近底部自动翻页 |
| 日期分组 | 按拍摄时间分组，组标题吸顶（`2026 年 11 月 24 日 星期一`），显示当天张数 |
| 年份索引 | 右侧年份条，点击跳转，滚动时高亮当前年份 |
| 搜索 | 文件名 / 相册 / 目录 / 设备 / 机型，350ms 防抖，服务端 `q` 参数 |
| 筛选 | 文件夹（全部 / DCIM/Camera / Pictures/… / 未分类）、类型（照片 / 视频）、有定位、年份 |
| 排序 | 按拍摄时间，缺拍摄时间时回退上传时间 |
| 骨架屏 | 首屏加载占位，不是白屏 |
| 空态 / 错误态 | 未登录、连不上、筛选无结果分别有对应文案与操作按钮 |
| 选择模式 | 底部操作条：`已选 N 张`、全选 / 取消全选、还原、删除 |
| 批量删除 | 二次确认，说明「只进 NAS 回收站，清空才真正删磁盘」 |
| 「更多」菜单 | 收拢刷新、批量还原、查看统计等低频操作 |

### 2.3 查看与播放

| 功能 | 说明 |
|---|---|
| 原图查看 | 显示文件名、时间、大小、机型、相册、GPS 信息；含位置的可跳地图 |
| 内置视频播放器 | media3 / ExoPlayer，带鉴权头直接拉原文件，不用先下载 |
| 拖进度条 | 依赖服务端 HTTP Range（206），不支持的旧服务端会退化成从头拉 |
| 错误提示说人话 | 编码解不了（HEVC / 4K）、登录过期、连不上 NAS 各有对应文案，可一键重试 |
| 视频封面 | 服务端生成缩略图，列表里不是黑块 |

### 2.4 还原

| 功能 | 说明 |
|---|---|
| 一键还原全部 | 从 NAS 拉回本机相册，写回原目录（DCIM/Camera 等） |
| 选中还原 | 相册页选几张再还原 |
| 单张还原 | 详情页 / 大图页单独还原 |
| 冲突策略 | 三选一：**跳过**（手机已有的不动，只补缺的）/ **留两份**（新增副本）/ **覆盖**（仅能覆盖自己写入的文件，系统相机、微信保存的会自动降级成留两份） |
| 进度与取消 | 顶部进度条显示第几张 / 共几张、当前文件名，可取消；系统通知同步显示 |
| EXIF 保真 | 写回时拍摄时间按 UTC 解析并转本地时区，GPS、机型一起写回 |
| 去重 | 按内容指纹判断，重复点「一键还原」不会产生副本 |

### 2.5 回收站

| 功能 | 说明 |
|---|---|
| 查看 | 按日期分组的已删除照片 / 视频 |
| 还原 | 单张或批量恢复到图库 |
| 永久删除 | 单张或清空，二次确认 |
| 与网页端一致 | 手机和网页看到的是同一个回收站 |

### 2.6 账号与连接

| 功能 | 说明 |
|---|---|
| 双地址 | 「内网地址（优先）」+「外网地址（备用）」，2 秒探测内网失败自动切外网 |
| 登录 | 账号密码换 token，token 存本机 |
| 记住密码 | 勾选后后台任务 token 过期会自动重登一次；不勾则要手动重登 |
| 身份显示 | 卡片显示当前登录身份（如 `已登录：demo（管理员）`），成功蓝色、失败红色 |
| 退出登录 | 清 token，后台任务停止 |
| 测试连接 | 单独测地址+账号是否可用，显示延迟与服务端版本 |
| 稳定设备 ID | 卸载重装不变；支持自定义（4~64 位字母数字点下划线短横线） |

### 2.7 体验与无障碍

| 功能 | 说明 |
|---|---|
| 首页 | 连接卡（状态 / 延迟 / 当前走内网还是外网 / 服务端版本）、存储概况、最近备份缩略图、未配置时三步引导 |
| 从设置登录后自动刷新 | 回首页立即显示新状态，不用杀进程 |
| TalkBack | 缩略图整格一句话（`文件名，照片，11月24日 16:30，含位置，相册 DCIM`），内部元素不再重复朗读 |
| 标题语义 | 日期分组标题标记为 heading，可整段跳读 |
| 年份索引语义 | 读作「2026 年」，当前项附加「当前」状态 |
| 包体 | R8（minify + shrinkResources）后 **5.9MB** |

## 3. 服务端（FastAPI + SQLite）

### 3.1 存储与索引

| 功能 | 说明 |
|---|---|
| 原样落盘 | 上传字节原封不动写入 `<数据目录>/photos/…`，不做任何转码 |
| SQLite 索引 | `index.db` 记录文件名、大小、SHA256、拍摄时间、GPS、机型、相册、目录、设备 |
| 内容级去重 | 同一份字节磁盘只存一份；不同用户各有记录、互不干扰 |
| 缩略图 | Pillow 生成，HEIC / HEIF 走 `pillow-heif`；视频用上传端给的封面 |
| 软删除 | 删除 = 进回收站（`deleted=1`），清空回收站才真删磁盘 |
| 完整性巡检 | 管理员可跑一遍，检查索引与磁盘是否对得上 |

### 3.2 网页管理端

浏览器打开 `http://<NAS-IP>:8765`，五个页签：

| 页签 | 功能 |
|---|---|
| **照片** | 统计（照片 / 视频数量、总大小）、按拍摄日期分组、搜索、按用户筛选（管理员）、按文件夹筛选、批量选择 + 全选 + 删除、点缩略图看原图、分页 |
| **回收站** | 按日期查看、批量选择、恢复所选、永久删除所选 |
| **用户**（管理员） | 新建账号、改角色、禁用 / 启用、重置密码、删除账号；用户列表渲染失败会把错误显示出来 |
| **维护**（管理员） | 完整性巡检、清空回收站、改自己密码 |
| **关于** | 服务端版本、页面构建时间、当前账号、健康状态、使用教程 |

- 缩略图 / 原文件用 **HttpOnly Cookie** 鉴权，URL 里不再带 token。
- 删除用**批量接口**，选几百张也只发一个请求。
- 兼容旧版 App：仍接受 URL 上的 `?token=`。

### 3.3 用户与权限

| 角色 | 看照片 | 用户管理 |
|---|---|---|
| 普通用户 | 只看自己备份的 | 不行 |
| 管理员 | 全部，可按用户筛选 | 可以 |

- 越权一律返回 **404**（不透露「存在但没权限」）。
- 改密码 / 禁用账号会让该用户**已发出的所有 token 立即失效**（`token_epoch`）。
- 密码 PBKDF2-SHA256，默认 60 万轮，下限 8 位。
- 用户名字符集限制：2~32 位，禁空格、引号、尖括号、斜杠、分号、反引号；显示名过滤不可打印字符。
- 登录失败限流：连续输错 N 次锁定一段时间。
- 初始管理员由 `INIT_ADMIN_USER` / `INIT_ADMIN_PASSWORD` 决定，启动日志会打印。

### 3.4 传输与安全

| 功能 | 说明 |
|---|---|
| HTTP Range | `Accept-Ranges: bytes`，请求带 `Range` 时返回 `206` + `Content-Range`，支持 `bytes=-N` 后缀区间，越界回 `416`。视频拖动、MP4 `moov` 读取都靠它 |
| 端口 | 原生包默认 8765（`manifest service_port`）；Docker 部署另把 8766 映射成 HTTP 兼容口，方便内网直接填 `http://NAS-IP:8766` |
| 自签 HTTPS | 支持 uvicorn 自己监听 HTTPS（证书上传 / 开关），HSTS 只在真的 HTTPS 下发送，cookie `secure` 跟随协议 |
| 反向代理 | 支持子路径部署（飞牛统一网关），`URL_PREFIX` 控制 |
| 安全响应头 | `X-Content-Type-Options`、`Referrer-Policy`、`Cache-Control: no-store` 等 |

### 3.5 API 一览

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/health` | 健康检查 + 版本 |
| POST | `/api/ping` | 连通性 / 延迟测试 |
| POST | `/api/auth/login` · `logout` · `password` | 登录 / 登出 / 改密码 |
| GET | `/api/auth/me` | 当前身份 |
| GET/POST/PATCH/DELETE | `/api/admin/users…` | 用户增删改查、重置密码、启禁用 |
| POST | `/api/photos/exists` | 批量问「这些指纹是否已存在」（备份去重） |
| POST | `/api/upload` | 上传原文件（含 EXIF / 拍摄时间 / GPS） |
| GET | `/api/photos` | 列表：分页、搜索 `q`、文件夹、类型、年份、用户 |
| GET | `/api/photos/{id}` | 单条详情 |

## 4. 部署与交付

### 4.1 飞牛 fnOS 原生包（推荐）

| 功能 | 说明 |
|---|---|
| 不依赖 Docker | 装完直接用系统 `python3` 跑 uvicorn，依赖从包内 `wheelhouse` 离线安装 |
| 双架构 | `photovault-native-2.0.5-x86.fpk`（x86） / `-arm.fpk`（aarch64）；`manifest platform` 不同，装错架构飞牛会拒绝 |
| 数据目录可填 | 安装向导里指定（`pv_data_dir`），不写死在应用目录，卸载重装不丢照片 |
| 生命周期脚本 | `cmd/main start/stop/status`，端口 8765，`ctl_stop=true` |
| 升级 | `upgrade_*` 脚本保留数据目录，只换代码与依赖 |
| 构建 | GitHub Actions `.github/workflows/build-native-fpk.yml`：按目标架构 `pip download` 对应 manylinux wheel（cp311）+ 改 `platform` + `fnpack build` |

### 4.2 Docker

| 功能 | 说明 |
|---|---|
| Compose 一键起 | `server/docker-compose.yml`，数据卷挂到宿主机 |
| GHCR 镜像 | `ghcr.io/lijiansen7/photovault`，多架构 |
| 离线包 | `photovault-offline-*.fpk`：镜像 `docker save` 进包，装的时候不用联网拉 |
| 环境变量 | `DATA_DIR`、`ACCESS_TOKEN`、`INIT_ADMIN_*`、`TOKEN_TTL_HOURS`、`MIN_PASSWORD_LEN`、`URL_PREFIX`、`LOG_LEVEL` 等 |

### 4.3 CI

| 工作流 | 作用 |
|---|---|
| `build-native-fpk.yml` | 原生包 x86 / arm 双架构，tag 时自动附到 Release |
| `build-fpk.yml` | Docker 离线包（`docker buildx` + QEMU） |
| `docker-publish.yml` | 构建并推送 GHCR 镜像 |
| `tests.yml` | 服务端自检脚本（不起服务） |

## 5. 已知限制

| 限制 | 说明 |
|---|---|
| 默认 HTTP 明文 | 账号密码与 token 在网络上裸奔。家庭内网可接受，外网访问务必套 HTTPS |
| arm 包未真机验证 | `photovault-native-2.0.5-arm.fpk` 只做了内容校验（aarch64 wheel + `platform=arm`），没在 arm 机器上实装过 |
| Release 包是 debug 签名 | 仓库没有 `release.keystore`，`assembleRelease` 出的是 unsigned；实际发版走 `assembleDebug`（同样开了 R8），签名为 Android 调试 key，保证能覆盖安装 |
| 没有双指缩放 | 1.3.2 曾有，2.0 相册页重做时未带回；大图查看目前是「适应屏幕」单档 |
| 视频缩略图依赖上传端 | 服务端不内置视频解码（不引 ffmpeg），手机没给封面时列表里是占位图 |
| 单机 SQLite | 不支持多实例横向扩展；家庭场景够用 |
| 无相册「智能分类」 | 不做人脸 / 场景识别，只有目录、时间、机型这些元数据维度 |
